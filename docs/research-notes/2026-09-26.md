## 결정 사항과 이유
- **1차 범위를 인수분해 → 이차방정식 한 단원으로 제한**
  - 이유: 선행 개념 보충(인수분해)을 보여줄 수 있는 가장 작은 단원부터 완성하고 확장하기 위함.
- **문제는 직접 구축한 문제 은행 사용, 자유 입력은 이후로 연기**
  - 이유: 자유 입력은 개념 태깅을 LLM에 의존해야 해서 신뢰성이 낮음.
- **LLM: o1 대신 저가·고속 모델 사용, 모델명은 .env에서 설정**
  - 이유: o1은 비싸고 느려 다회 대화형 튜터와 실험에 부적합. 풀이 정확성은 SymPy 검증으로 보완.
- **SymPy 검증을 AI 풀이 점검뿐 아니라 학생 답변 채점에도 사용**
  - 이유: 학습자 모델의 입력(정오 판정)을 LLM 판단이 아닌 결정적 계산으로 얻기 위함.
- **튜터 LLM과 풀이 LLM을 분리**
  - 이유: 튜터가 정답을 모르게 하여 정답 유출을 구조적으로 방지.

## 채점 엔진 설계 결정
- **오답의 정도를 계수 비교로 구분** (내 아이디어: 계산 실수에도 정도 차이가 있음)
  - 학생 답을 전개해 원래 식과 계수별로 비교
  - 부호만 다름 → 경미(부호 실수) / 계수 1개 다름 → 부분 / 2개 이상 → 먼 오답
  - x²+bx+c 꼴에서는 상수항 = 곱 조건, 일차항 = 합 조건이므로 어떤 조건을 놓쳤는지까지 추정
  - 해 단계: 부호 반전(x=-2, x=-3) → 경미, 일부 누락 → 부분
  - 한계: 원인 "추정"일 뿐이므로 반복 여부(학습자 이력)와 함께 판단해야 함
- **계산 실수 vs 개념 오류는 채점 엔진이 아니라 학습자 모델이 이력으로 판정**
- **보안**: SymPy `parse_expr`는 내부적으로 eval을 사용 → 숫자·x·연산자·괄호·sqrt 외 문자는 파싱 전에 차단
- **인수분해 완료 여부는 식을 계산하지 않은 상태(evaluate=False)로 판단**
  - 이유: SymPy는 `3(x-2)`를 자동으로 `3x-6`으로 전개해 버려 원래 형태를 잃음
  - `x(3x-6)`처럼 공통인수가 남은 경우도 "인수분해 미완료"로 판정
- **정답 유출 방지**: 해 단계 채점 결과 설명(detail)에 정답 값을 넣지 않음 (튜터 LLM에 전달되므로)

## 오류 유형 구조 개선 (내 질문에서 출발)
- 문제: ErrorType에 "합 조건 누락"처럼 인수분해에서만 나오는 유형이 섞여 있어, 단원을 추가할수록 enum이 커지고
  이를 사용하는 학습자 모델·튜터를 매번 수정해야 함
- 해결: 두 층으로 분리
  - `ErrorType` (7개 고정): 없음 / 부호 실수 / 풀이 미완료 / 일부 누락 / 오답 / 무응답 / 해석 불가 → **학습자 모델이 사용**
  - `diagnosis` (자유 문자열): 합 조건 누락, 곱 조건 누락, 인수분해 미완료 등 → **튜터 힌트 문구와 분석에만 사용**
- 원칙: 학습자 모델은 "얼마나 틀렸나"(severity, error)만, 튜터는 "무엇을 틀렸나"(diagnosis)까지 본다

## 범위 점검: 대수 영역(방정식·부등식·함수) 확장 시 걸리는 부분
- 이미 일반적인 부분: 단계 유형별 분기 구조, 해집합 채점, 값 채점, 계수 비교(부호/1개/여러 개), 개념 그래프
- 확장 시 수정이 필요한 부분 (중간보고서 범위에서는 구현하지 않음)
  1. 입력 필터에 부등호(<, >, ≤, ≥)가 없음 → 부등식 답 해석 불가. 부등식 단원 추가 시 `inequality` 단계 유형 추가
  2. 문제의 `expression`은 "식 = 0" 형태를 가정 → 부등식은 부등호 방향 정보가 추가로 필요
  3. 변수가 x 하나뿐 → 함수(y=…)와 좌표 답 "(2, -1)" 처리 불가. 함수 단원 추가 시 y 허용과 `point` 단계 유형 추가
- 세 가지 모두 새 단계 유형 함수를 추가하는 방식으로 해결 가능하고, 학습자 모델·튜터는 수정하지 않아도 됨

## 풀이 LLM + 검증·재생성 (실험 1 준비)
- `mathtutor/solver.py`: 풀이 생성 → 채점 엔진으로 단계별 검증 → 실패 시 실패 내용을 피드백으로 주고 재생성 (최대 3회)
- 채점 엔진을 학생 답 채점과 AI 풀이 검증에 **같은 코드로** 사용 (제안서 3.2 구현)
- 문제 은행의 해가 사람이 적은 값이 아니라 SymPy 계산 결과와 일치하는지 테스트로 확인
- 파일럿 (15문제 × 1회)
  - gpt-5.4-mini, 추론 low: 첫 시도 15/15 정답 → 이 난이도에서는 검증 전후 차이가 나타나지 않음
  - gpt-5.4-nano, 추론 none: 첫 시도 14/15, 검증 후 15/15
  - E7 사례: 판별식을 0으로 잘못 계산(부호 실수) → "중근"이라고 판단해 해도 틀림.
    검증 피드백을 받고 2차 시도에서 판별식 8, 해 1±√2로 수정 → **오류 전파를 검증이 차단한 사례**
- 고민: 쉬운 문제에서는 좋은 모델이 거의 틀리지 않아 검증 효과를 보이기 어려움
  → 결정: 결과를 좋게 보이려 조건을 바꾸지 않고, **모델·추론 강도별로 비교**하여
    "검증이 있으면 더 저렴한 설정도 신뢰성을 확보할 수 있는가"를 보기로 함

- 최대 시도(3회) 후에도 실패해 차단된 경우: 모든 설정에서 0
- 오류 사례
  - mini/none F6: 단계 수를 지키지 않은 **형식 오류** → 피드백 후 수정
  - nano/none E2: (x-4)(x+3) → 채점 엔진이 **부호 실수(경미)**로 진단, 해도 4, -3으로 부호가 전파됨 → 2차에 수정
  - nano/none E7 (2회, 같은 패턴 재현): 판별식 0 → "중근" 해 1 → 2차에 수정
- 해석 메모 (보고서에서 내 말로 다시 쓸 것)
  - 오류는 모두 **앞 단계의 실수가 뒤 단계로 전파**되는 형태 → 단계별 검증의 의미
  - 학생 오답용으로 만든 계수 비교 진단이 LLM 오답에도 그대로 작동
  - 한계: 문제가 쉬워 오류 수가 적음(최대 3/75). 어려운 문제는 최종 보고서에서

## 튜터 대화 루프 (최소 버전)
- `mathtutor/learner.py`: 규칙 기반 학습자 모델 (severity만 사용)
  - 정답 → 힌트 레벨 +1 (도움 줄임), 첫 시도 정답이면 개념 상태 한 단계 상승
  - 경미 → 변화 없음 / 부분 → 레벨 -1, 같은 개념에서 2번 반복되면 상태 하락 / 먼 오답·무응답 → 레벨 -1, 상태 하락
  - 상태가 "보충 필요"가 되면 튜터에게 선행 개념(개념 그래프)을 함께 전달
- `mathtutor/tutor.py`: 한 턴 = ① 학생 발화에서 수식 추출(LLM) → ② SymPy 채점 → ③ 학습자 모델 갱신 → ④ 튜터 발화 생성(LLM)
  - 튜터 LLM에는 정답을 주지 않고 채점 결과·진단·힌트 레벨만 전달
  - 튜터 발화에 아직 안 푼 단계의 정답이 들어 있으면 다시 생성 (정답 유출 방지)
  - 뒤 단계의 답을 먼저 말하면 그 단계까지 인정 (단계 건너뛰기)
- `mathtutor/cli.py`: 대화 CLI, 대본 파일로 재생 가능, 대화 기록을 `experiments/results/dialogs/`에 저장

### 데모에서 발견한 버그와 수정
- "(x-1)(x-6) 인가요?"처럼 물음표를 붙인 답을 추출 LLM이 "질문"으로 분류 → **채점이 건너뛰어지고 튜터 LLM이 스스로 판단**
  → "판정은 SymPy만" 원칙 위반. 수정: 의도와 관계없이 수식이 있으면 항상 채점 + 추출 지시문 보완
- 튜터가 LaTeX·마크다운을 출력 → 평문 수식을 쓰도록 지시문 수정
- 수정 후 데모: "합 조건 누락" 진단이 전달되어 튜터가 "곱은 맞지만 합이 -5가 되어야 해요"라고 짚음,
  정답 유출 시도 1회를 방지 장치가 잡아 재생성, 정답을 조르는 학생에게도 끝까지 정답 비공개
